\section{Setup}

Pusher-B (b10) transformer trunks are taken from two pretraining runs on the
pure-reward task: PPO (\texttt{rl\_b10}, checkpoints at iterations 4, 8 and
143) and PPO with a next-token cross-entropy auxiliary loss (PPO+CE,
\texttt{rl\_b10\_aux\_ce}, checkpoints at iterations 4, 8 and 211). Each
checkpoint is converted into a pure-JAX trunk and fine-tuned with PPO on the
guess-or-pass task: actions 0/1 guess the pending token (reward $+1$ if
correct, $-c$ otherwise) and action 2 passes (reward $0$). Every run uses
seed 42 and 10M env steps. The trunk is either fine-tuned together with the
new heads (\emph{full trunk}) or frozen so that only the heads train
(\emph{frozen trunk}); a scratch run with a randomly initialised trunk is
the reference. Costs $c\in\{1, 1.5, 2\}$ were run with a full trunk; at
$c=1$ and $c=1.5$ every source and the scratch run reach the Bayes-optimal
reward, so the frozen-trunk phase and all figures below use $c=2$, the only
rung that separates trunks. Results and the plotting script live in
\texttt{experiments/pusher\_b10\_guess\_or\_pass\_jax\_2026\_10}.

\section{Observations}

\begin{itemize}
  \item At $c=2$ the scratch run and both iteration-4 trunks collapse to
    always-pass (pass rate $\approx 0.99$). PPO iteration 143, PPO+CE
    iteration 8 and PPO+CE iteration 211 reach roughly 93\% of the Bayes
    reward with a trainable trunk.
  \item The clearest CE effect is at iteration 8 (0.075 vs.\ 0.039), but it
    is a fine-tunability effect: with the trunk frozen, PPO+CE iteration 8
    falls back to 0, so the representation is not linearly readable by a
    fresh head at that point.
  \item Frozen-trunk transfer works only from the late checkpoints, and
    there PPO+CE (0.065) is ahead of PPO (0.050).
\end{itemize}

\paragraph{Caveats.} Single seed (42); the late PPO+CE checkpoint had
$\sim$60M pretraining steps versus $\sim$116M for late PPO.
